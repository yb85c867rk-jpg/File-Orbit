FileOrbit native file-read failure investigation r80

Confirmed source-backed attachment defect:
- decodeBackup() validated source slices with sha256, then retained the raw blob.slice(...) for each attachment.
- Runtime registry adopted those slices, which could remain backed by the opened .fileorbit File.
- Overwriting the same handle could invalidate previously acquired File/slice reads; later encoding failed while reading an existing attachment.
- The new PDF itself and viewer were not the cause.

Correction:
- decodeBackup reads each validated attachment range into an ArrayBuffer and constructs a new detached Blob before returning/adoption.
- Bounded diagnostics:
  - decode: attachment-read-failed includes attachment originalName/id, error name/message (no bytes/content).
  - encode: attachment-read-failed includes originalName/runtime id, error name/message.
- Validation/hashes/metadata/IDs/cancellation/limits unchanged. Save still completes only after write+close.
