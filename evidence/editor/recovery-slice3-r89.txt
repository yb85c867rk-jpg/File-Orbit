Production flow:
1. Startup: existing production open path lists recovery candidates once after stable empty state. Dialog appears only if candidates exist; Create/Open/import/editor start cancels pending discovery. Later/Escape close without writes.
2. Recover: claim exact source workspace/generation/checkpoint ID -> load and revalidate complete checkpoint/tree/metadata/hashes/detached bytes -> create independent child with exact forkedFrom identity -> reconstruct runtime registry via reconstructSavedMapRuntime -> install through installCandidateEnvironment -> publish only after authoritative commit.
3. Adopt: scheduler.adoptWorkspace(child) validates control/token/state, invalidates outgoing ownership, adopts durable controlVersion, keeps session/dataset guards. Subsequent edits/Undo/Redo/Save use child.
4. Durability: child baseline checkpoint is secured before repository.supersedeRecoverySource(source exact ID/generation, child exact checkpoint). Failures preserve source and live installed work; claim is released. Source advancement rejects supersession without deleting newer source.
5. Discard: claim exact selected candidate, then discard exact workspace/token/checkpoint/claim; revalidate and refresh on claimed/advanced. Later performs no writes.
