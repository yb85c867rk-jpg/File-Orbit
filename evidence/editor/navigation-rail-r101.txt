FileOrbit navigation rail / unified Open / Download r101

Implemented:
- Right-side collapsible nav rail, collapsed icons-only; expanded labels.
- Rail actions order: Create Map, Open File, Save, Save As, Settings.
- Settings contains existing Dark/Light theme and Previous local maps.
- Header/Mobile menu copies of primary actions removed; header retains document name, save status, storage help, fixture controls.
- Desktop rail reserves 64px collapsed/204px expanded and graph resizes through existing ResizeObserver/scheduleViewportResize pipeline.
- Phone <=560: rail fixed compact 56px, layout reserves 64px so collapsed rail does not cover graph; expanded rail is a fixed overlay (max 210px), scrollable and inside viewport.
- Rail has 44px targets, aria-expanded/controls, focus-visible, tooltips via shared tooltip controller, reduced-motion transition guard.
- Download moved after Fullscreen in graph toolbar; local SVG; accessible name "Download map copy"; title/tooltip Download.
- Download exports authoritative map/attachments as .map (safeDocumentFilename), does not change active destination or dirty state; handoff feedback and cleanup retained.

Behavior differences documented:
- Writable .map Open: active writable handle, clean baseline, Save can overwrite.
- Fallback Open: no handle, mode download, clean baseline, Save is unconfirmed download.
- Legacy .fileorbit: readable via Open; writable handle intentionally not adopted; mode download, Save prompts .map copy; never auto-rewrites source.
- Import Backup internal decode/install path remains for compatibility tests/fallback, but separate user-facing Import action removed.
- .map/.fileorbit validation uses decodeBackup magic/content, not extension alone.
- Previous local maps remain IndexedDB-backed and accessible in Settings; startup recovery untouched.
