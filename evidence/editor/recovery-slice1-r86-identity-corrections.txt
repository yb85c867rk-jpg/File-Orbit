FileOrbit Recovery Slice 1 identity corrections r86

Scope: storage layer only. No scheduler, startup prompt/install, Save retirement wiring, main.mjs, editor/history/graph/viewer, user-document, capacity, pruning, or migration changes. Slice 1 remains not accepted.

R1 — complete source identity for fork creation
Root cause: createRecoveryWorkspace checked source active generation and checkpoint ID, but did not compare forkedFrom.workspaceToken with the stored source token, and did not require the claim's checkpointId/generation to match the requested fork. A wrong valid-format token or a generation-1 claim could create a child for generation 2.
Correction: inside the child-creation readwrite transaction, require exact agreement among:
- source workspace key, stored source.workspaceId, forkedFrom.workspaceId;
- stored source.workspaceToken, forkedFrom.workspaceToken;
- forkedFrom checkpoint ID/generation, source active generation, source checkpoint record workspace ID/token/ID/generation;
- claim ID, claim.checkpointId, claim.checkpointGeneration;
- source active state, source claim presence, unexpired claim.
All checks happen before workspaces.put(child). Rejections abort with no child/control write. forkedFrom is persisted from the validated captured identity only, never substituted with current values.

R2 — checkpoint identity bound to workspace token
Root cause: loadRecoveryCheckpoint validated the checkpoint schema but not checkpoint.workspaceId/workspaceToken against the containing workspace control, so a checkpoint with a corrupted token was returned.
Correction: shared checkpointIdentityError() validates:
- checkpoint.workspaceId === workspace.workspaceId and expected workspace ID;
- checkpoint.workspaceToken === workspace.workspaceToken and expected token;
- checkpoint.checkpointGeneration === expected active generation;
- checkpoint.checkpointId === expected checkpoint ID when supplied.
Applied at:
- loadRecoveryCheckpoint (throws recovery-checkpoint-identity-mismatch);
- claimSource (throws before issuing a claim);
- listRecoveryCandidates (identity-inconsistent checkpoint is not eligible);
- discardRecoveryWorkspace (identity before deletion);
- supersedeRecoverySource (source and child identity rechecked atomically; child preflight failure remains child-not-durable).
No automatic repair, rewrite, or deletion occurs.
