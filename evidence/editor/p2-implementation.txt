FileOrbit P2 implementation evidence

User-reported: Open → Add PDF → Save → refresh → Open works in their browser. Recorded only as that flow, not quota/cross-tab/durability.

Implemented:
- Library usage: application attachment bytes/cap + separate browser origin estimate/persisted state; unknown states; optional Request persistent storage with granted/not-granted/unavailable/error.
- Stale-generation conflict dialog: Cancel, Reload saved version with discard confirmation, Save as new copy. Copy uses new map ID, preserves node IDs/attachment bytes, independent rows, original unchanged; identity publishes after commit only.
- Repository lifecycle: close invalidates pending open; late connection closes and cannot publish; versionchange blocks reopen; snapshot/own payload preserved.
- Error messages for quota, application cap, unavailable IDB, blocked, versionchange/schema, abort, inconsistent/missing attachments.
- Teardown invalidates operation tokens, closes repo/dialogs; synchronous beforeunload warning for committed dirty/draft; no async save.
- Accounting/deletion behavior preserved.
