FileOrbit YAML attachment viewing r100

Confirmed root cause:
- attachment-classification.js only classified txt/text/log as text.
- .yaml/.yml were not extension-recognized, and YAML MIME types were not text MIME.
- A YAML file with empty or application/octet-stream MIME therefore classified as generic.
- resolveAttachmentViewerTarget() permits generic only for recognized image signatures; YAML fell through to state unsupported.
- Repro before correction: classifyAttachment({name:'name.yaml',mime:'',prefix:empty}) => format generic; viewer => {ok:false,state:'unsupported'}.

Correction:
- YAML_EXTENSIONS = yaml, yml (extensionOf is lowercase, so case-insensitive).
- YAML MIME types recognized as text: application/yaml, application/x-yaml, application/vnd.yaml, text/yaml, text/x-yaml.
- YAML extension classification is text with badge YAML, regardless of empty/octet-stream MIME; binary MIME conflict remains needs-review.
- Existing generic classifications from older saved YAML attachments are accepted by extension in the viewer, with no file-byte change.
- The existing plain-text viewer is used: TextDecoder UTF-8, BOM stripped, pre.textContent literal, 1 MiB truncation, scroll/Close/focus unchanged.
- PDF/image/text routing unchanged.
